# Debloated Darwin patch series

This worktree keeps upstream FEX-2610 (`14c92681f4d62cf84d901460e0358de09c8847a7`) unchanged. `patches/series` is the application order; `provenance.json` records the upstream and imported revisions, patch SHA-256 values, and expected applied source tree.

The original seventeen patches are copied byte-for-byte from wine-build-new commit `396ecb609d07bf8f90905070d53b92f0a65d49bf` (`cleanup/fex-patch-source-debloat`, FEX package revision 10). A final local correctness patch fixes committed register state at faults and arithmetic immediate construction. Hadron and Arknights patches are regular files here, so this queue does not depend on the Wine checkout or its symlinks. Hadron's original submodule path is spelled `third-party/hardon`.

The imported license texts are retained at `patches/hadron/LICENSE` (David Andrews, MIT) and `patches/arknights-macos-runtime/LICENSE` (MPL 2.0). Preserve them when redistributing this queue.

The order is five Hadron Darwin/64 KiB guard/hardware-TSO/W^X patches, eleven imported local correctness and optimization patches (including Hadron JIT memory/invalidation), Arknights carried-EFLAGS handling, then the new local `0012` exception/immediate correction. The final debloat already folds the former local patches 0012-0014 into their feature owners; those superseded patches are not the new correction and must not be added again. The corrected translator uses cache namespace `0xA624` so code generated by the faulty allocator cannot be reused.

## Apply to a fresh upstream source

Run from this worktree's root. `build/local/source` must not already exist.

```sh
git clone --shared --no-checkout . build/local/source
git -C build/local/source switch --detach 14c92681f4d62cf84d901460e0358de09c8847a7
while IFS= read -r entry; do
    patch -d build/local/source -p1 -F0 --batch --no-backup-if-mismatch \
        -i "$PWD/Darwin/patches/$entry" || exit
done < Darwin/patches/series
git -C build/local/source add --all
git -C build/local/source write-tree
```

The resulting source tree must be `ca8a669addd2c9c257a1ad19c9aeee7f6ea80d43`. This is a tree object, not a source commit. Application must require no offsets or fuzz. Keep applied sources and outputs below `build/local/`; edit the patch queue to maintain this distribution.

Initialize only the build dependencies at their upstream gitlink revisions:

```sh
git -C build/local/source submodule update --init \
    External/fmt External/range-v3 External/rpmalloc \
    External/unordered_dense External/xxhash Source/Common/cpp-optparse
```

## Native macOS ARM64 build

Use CMake, Ninja, Python 3, the macOS SDK and llvm-mingw. The commands follow the source Portfile's Release recipe. Stock llvm-mingw must keep `FEX_MINGW_PRESERVE_ALL=OFF` because its Windows AArch64 `preserve_all` code generation is unsuitable for these fallbacks.

```sh
export LLVM_MINGW=/opt/llvm-mingw-20260616-ucrt-macos-universal
export PATH="$LLVM_MINGW/bin:$PATH"
SOURCE="$PWD/build/local/source"
OUTPUT="$PWD/build/local/native"
for target in arm64ec wow64; do
    triple=arm64ec-w64-mingw32
    if [ "$target" = wow64 ]; then triple=aarch64-w64-mingw32; fi
    cmake -S "$SOURCE" -B "$OUTPUT/build-$target" -G Ninja \
        -DCMAKE_BUILD_TYPE=Release -DCMAKE_POLICY_VERSION_MINIMUM=3.5 \
        -DCMAKE_TOOLCHAIN_FILE="$SOURCE/Data/CMake/toolchain_mingw.cmake" \
        -DMINGW_TRIPLE="$triple" -DENABLE_LTO=OFF -DENABLE_ASSERTIONS=OFF \
        -DENABLE_JEMALLOC_GLIBC_ALLOC=OFF -DBUILD_TESTING=OFF \
        -DTUNE_ARCH=generic -DTUNE_CPU=none -DRANGES_NATIVE=OFF \
        -DFEX_MINGW_PRESERVE_ALL=OFF \
        -DPython_EXECUTABLE="$(command -v python3)" \
        -DCMAKE_CXX_COMPILER_CLANG_SCAN_DEPS="$LLVM_MINGW/bin/clang-scan-deps" || exit
    cmake --build "$OUTPUT/build-$target" --target "${target}fex" --parallel 8 || exit
done
cmake -S "$SOURCE/Source/Windows/UnixLib" -B "$OUTPUT/build-unix" -G Ninja \
    -DCMAKE_BUILD_TYPE=Release -DCMAKE_CXX_COMPILER=/usr/bin/clang++ \
    -DCMAKE_OSX_ARCHITECTURES=arm64
cmake --build "$OUTPUT/build-unix" --parallel 8
```

The Arknights patch requires the [paired Wine EFLAGS transport patch](https://github.com/riverfog7/wine-build-new/blob/396ecb609d07bf8f90905070d53b92f0a65d49bf/patches/wine/arknights-macos-runtime/0001-ntdll-carry-eflags-af-df.patch) when extra flag transport is enabled. Apply `patches/wine/0001-ntdll-preserve-carried-eflags-on-continuation.patch` to that Wine source as well: conversion alone does not preserve AF/DF through continuation and thread-context serialization. This Wine companion is recorded separately in `provenance.json` and is not part of the FEX `series`. Both sides use `LMISXH_AKMOCL_EFLAGS`; an unset value or exactly `1` enables it. Without the paired Wine patch, disable it before starting any Wine process:

```sh
export LMISXH_AKMOCL_EFLAGS=0
```

An unpaired Wine runtime does not transport PF/AF/DF, so enabling this feature there can clear those flags during context synchronization. The imported seventeen-patch baseline's 43 runs used the opt-out; the corrected Wine 11.20 validation uses the paired transport and continuation fix.

Stage `build-arm64ec/Bin/libarm64ecfex.dll` as both `libarm64ecfex.dll` and `xtajit64.dll`, and `build-wow64/Bin/libwow64fex.dll` as both `libwow64fex.dll` and `xtajit.dll`, in a private Wine runtime's `lib/wine/aarch64-windows/`. Both native helpers in `build-unix/` belong in its `lib/wine/aarch64-unix/`. Use a fresh private Wine prefix and verify the loaded DLL and helper hashes; replacing only the xtajit aliases can leave Wine loading an older builtin implementation.

### Exception correctness follow-up

`build/local/exception-fix-20261108/` contains the corrected eighteen-patch replay and both rebuilt PE translators/native helpers. The replay matches the source tree above without offsets or fuzz. The original seventeen-patch validation in the preceding paragraph remains historical evidence.

The DIV full-check failure removed a completed fixed-register store before a faulting load. The allocator now retains that state. The O0 failure came from constructing ADD/SUB through a logical-immediate builder before retargeting its opcode; their existing arithmetic flag builders now produce the result directly. The paired Wine fix preserves PF/AF/DF in emulated software contexts while retaining native PSTATE sanitization.

The corrected REP probe passes 31,247 cases, and the identical DIV O0 binary passes. The extended context probe passes its original eleven cases plus four PF/AF/DF Get/Set/Resume roundtrips; its new assertions fail on the original runtime. The REP comparison oracle now requires pre-instruction EFLAGS on a fault, as specified for [REPE/REPNE CMPS/SCAS](https://www.felixcloutier.com/x86/rep:repe:repz:repne:repnz#description), while retaining exact register, access, flag and restart checks. See `after-focused/result.json`, `context-before-poll/result.json`, and `context-after-poll/result.json` below that output directory. Initial context-fixture attempts timed out on a conditional-only loop; the final worker uses the existing backward-JMP suspension poll.

The final canonical runtime is `../D3Dalloy/build/local/wine1120-fex-exception-fixed-20261108-package/runtime` relative to the main checkout. All 23 reachable x64 regression rows pass with matching PE, native helper and ARM64 process identities, including three REP ordering configurations, all four DIV modes, context/APC, cache, SMC, JIT growth, hardware TSO and emulated JIT. Each REP row completes 31,247 checks. See `final-cpu/result.json` below the exception output directory. The separate fixed-low-address REP fixture and i386 startup remain blocked by Wine's existing address-mapping limitation; this follow-up does not claim those paths passed.
